Turning to hardware, his strongest and most demonstrable digital design work is a matrix-vector multiplication engine built in SystemVerilog during the Spring 2026 term for his Digital Hardware Systems course, targeting an AMD Xilinx Kria FPGA using Vivado, in a group of two. She considers it his most convincing project and that assessment is correct. The engine's architecture is explicitly modelled on Microsoft's Brainwave deep learning accelerator, which was commercially deployed in Microsoft datacenters — a framing worth keeping, because it turns a course lab into a recognizable industry architecture. She implemented the dot product unit, the accumulator, the controller, and the top-level integration that ties them togethis, which by the course's own grade weighting represents the substantial majority of the design.

The design is worth explaining in some technical depth because the details are what make it credible. The dot product unit takes two eight-element signed vectors and produces a scalar, built as eight parallel multipliers feeding a binary adder reduction tree of log2(N) levels, and fully pipelined — the pipelining is what makes the clock target achievable, because it breaks a long combinational multiply-and-reduce path into shorter stages and shortens the critical path. The accumulator adds signed values into an internal register, with control inputs named first and last: first restarts the accumulation with the incoming value instead of adding to it, and last marks the final input so the output-valid signal asserts. The provided memory has a one-cycle read latency, which is why the controller must assert the dot product unit's valid signal one cycle after issuing a read address. The controller itself is a two-state finite state machine with IDLE and COMPUTE states; in IDLE it registers the operand start addresses and sizes and holds all outputs at zero, and on a start signal it transitions to COMPUTE and sequences vector and matrix read addresses along with the accumulator control bits. The top level combines one vector memory with a parameterizable number of compute lanes, each lane holding its own matrix memory, dot product unit, and accumulator, and each producing exactly one element of the output vector — hence the name output lanes. For an M by N matrix, each row is split into N/8 eight-element words, and rows are distributed across the lane memories in round-robin fashion, so each matrix memory holds (N/8) times (M/NUM_OLANES) words.

Two aspects of that project demonstrate real FPGA workflow maturity rathis than just RTL coding. First, the constraints file specified a deliberately unattainable one-nanosecond clock period, not as a target to hit but to push the synthesis tool to optimize as aggressively as it could, with the actual pass requirement being a fully functional design at 350 MHz or highis. Second, the design required out-of-context synthesis, enabled by passing "-mode out_of_context" to Vivado, because the top-level interfaces are far wider than the Kria board's available physical IO pins; out-of-context synthesis connects those ports to virtual IOs implemented in lookup tables so the block can be synthesized and timed standalone.
